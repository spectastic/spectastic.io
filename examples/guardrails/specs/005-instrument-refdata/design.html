Design · 005-instrument-refdata

Instrument reference data

How we will build it — a module that has nothing to do with positions, and a rule that keeps it that way.

Status Accepted Spec 005-instrument-refdata Owner Position Keeping team Branch build-out Created 18 Sep 2026 Read time

A refdata package — Instrument, a CSV ReferenceFeedLoader, an in-memory ReferenceStore — with “its own module” made real by an ArchUnit isolation rule: nothing in refdata depends on hex and nothing in hex depends on refdata. No new dependency, no new store. Biggest risk is a future convenience import in either direction; the rule is what catches it.

Acknowledged on the merits: reference data has its own store, never reaches the positions store, the port or the bus, and the isolation rule below makes that a checked fact rather than an intention.

3 · Data model & contracts

The spec's Instrument lands as record Instrument(String symbol, String name, String currency, int lotSize). The feed is CSV with the header symbol,name,currency,lotSize; the bundled one at src/main/resources/refdata/instruments.csv is the default load.

Conceptual entityPhysical shapeNotes
Instrumentrecord Instrument(String symbol, String name, String currency, int lotSize)Keyed by symbol in the store; a reload replaces the whole map.
Reference feedCSV, header symbol,name,currency,lotSize, no quotingRead from a Reader, so a path or a classpath resource both work.

No interface: the store is in-process. A lookup endpoint would be a separate feature with its own contract.

6 · Approach

ReferenceFeedLoader.load(Reader) reads the header, checks the four column names, and returns a list of Instrument; ReferenceStore.load(List<Instrument>) replaces its map; lookup(symbol) returns an Optional. Main loads the bundled feed at start so the process has reference data, and otherwise ignores the package. The isolation rule is two @Test methods added to CoreRulesTest.

7 · Alternatives considered

What “its own module” should mean was the real question. Criteria: whether the boundary is enforced, build weight, and whether it stays honest as the codebase grows.

Package + ArchUnit isolation rule — chosen3 — fails the build3 — none28
Separate Gradle subproject3 — the compiler1 — a second build file, a second test task37
A package with no rule0 — convention only303

The subproject is the right answer for a real system and loses here only on weight; the example already gains a real second subproject with the consumer service (stage 10), which shows that shape too.

8 · Decisions

D-001 · “Own module” = the refdata package plus a two-way ArchUnit isolation rule

Status
Accepted
Context
Spec NFR-001 (should) wants separation from positions. The existing CoreRulesTest pattern expresses “package A never depends on package B” and was negatively checked in 001; grep shows no cross-reference today.
Decision drivers
enforced, not declared · zero build weight · reuse of the fitness-function pattern
Considered options
  • Package + isolation rule — chosen — + fails the build on the first cross-import. − A package boundary is weaker than a compile-time one.
  • Gradle subproject — + the compiler enforces it. − doubles the build files for forty lines of code.
  • Package only — − nothing enforces it.
Decision
xyz.briancorbin.pk.refdata; two @Test methods in CoreRulesTest: ..refdata.. depends on nothing in ..hex.., and ..hex.. on nothing in ..refdata... Not a scoped <spec-decision> — it governs no store.
Consequences
+ The “distance” the timeline narrates is a checked property. − Main (outside both) is the only place they meet.

D-002 · The feed is a four-column CSV read from a Reader; the bundled copy is a classpath resource

Status
Accepted
Context
The spec's feed is abstract; the example needs one that loads with no dependency. Gradle's processResources puts src/main/resources on the classpath.
Decision
Header symbol,name,currency,lotSize, comma-separated, no quoting; ReferenceFeedLoader.load(Reader) so a file path (a refresh) and the bundled resource (the default) share one parser.
Consequences
+ No CSV library; a refresh is “load another file”. − A name containing a comma is unsupported; recorded, not handled.
