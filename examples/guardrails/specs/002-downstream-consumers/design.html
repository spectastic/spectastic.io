Design · 002-downstream-consumers

Downstream consumers

How we will build it — and where ADR-0007 is born.

Status Accepted Spec 002-downstream-consumers Owner Position Keeping team Branch main Created 11 Mar 2024 Read time

Position mutation already flows through a port (001). We make the persistence adapter the single writer and the single emitter of PositionChanged, and record that as ADR-0007 (D-007) — with its fitness function (an ArchUnit boundary rule + a Semgrep content rule) authored at the same time — plus a defense-in-depth DB-grant backstop (D-008). This is the decision every later feature is checked against.

1 · Principles check

Ports-and-adapters (001) keeps the domain framework-free; this feature adds an outbound port for the event and makes the adapter the sole writer. The emission guarantee is enforced by a fitness function, not by hope — the whole point of ADR-0007.

2 · Technical context

Language / runtime
Java 21 on the Gradle build 001 bootstrapped (001/D-001); JDK-only domain.
Architecture
Hexagonal — the persistence adapter is the single writer + emitter; consumers subscribe to an in-memory bus.
Enforcement
ArchUnit (boundary) + Semgrep (content) + a DB grant (operational) — layered, per ADR-0007.

3 · Data model & contracts

No external contract. PositionChanged is an internal event (instrument, quantity, tradeId). The persistence port stays the only write surface; the event is emitted inside the same transaction (spec NFR-001).

6 · Approach

Add an outbound event port; the persistence adapter emits PositionChanged on every write, inside the transaction. Risk and P&L subscribe to a synchronous in-memory bus. Make the adapter the single writer and pin that with a fitness function (ADR-0007) so no later feature can add a second writer without failing the gate.

8 · Decisions

D-006 · Synchronous in-memory event bus for this milestone

Context. Durability is a later concern (spec out-of-scope). Decision. Emit synchronously inside the mutation transaction over an in-memory bus. Consequences. + A committed position and its event never diverge. − No replay yet.

 src/**/persistence/** xyz.briancorbin.pk.hex.persistence.. Every position change must emit PositionChanged so Risk, P&L, and the audit trail stay consistent; a direct write to the position store bypasses the emission and the audit hooks that live in the adapter.

D-007 · ADR-0007 — only the persistence adapter touches the data store

Context. Spec FR-004 requires a single emitter; the emission guarantee is only as strong as the boundary around the write. The domain reason is settlement consistency (KB-0001@2026-09-13): the book and its consumers must never diverge silently. Decision. Only xyz.briancorbin.pk.hex.persistence may reach the data-access APIs or write the positions store; enforced by an ArchUnit boundary rule now, a Semgrep content rule for the residual SQL case (added when JDBC arrives, feature 003), and a DB grant as the operational backstop (D-008). Consequences. + Every position change provably emits the event; a new writer fails the gate. − Legitimate new persistence code lives in the adapter package or extends the scope through a recorded amendment. Amended 13 Sep 2026. The decision now also names the store it governs and its owner — spectastic://briancorbin/position-keeper-guardrails/datastore/positions, owned by this service — so that in any other service a touch of the store is a violation even when cleanly layered in that service's own adapter: the defect there is ownership, not layering.

 db/** Even if a static rule is evaded, the database itself refuses a write to positions from any role but the adapter's.

D-008 · DB-grant backstop for the positions table

Context. Static rules can be evaded; a defense-in-depth layer belongs at the database. Grounded by the H2 grant spike in §5: a role without the grant is refused (90096), the adapter's role is not. Decision. A GRANT limits writes on positions to the adapter's role — db/grants.sql, applied by H2Database.open (003), and pinned by GrantBackstopTest. Consequences. + A final backstop below the static checks. − Not statically checkable at merge time — recorded as a none-with-reason so coverage reports it honestly; the runtime test proves the grant, not the diff.

10 · Risks & mitigations

A later feature adds a second writer, bypassing emission

Likelihood high over time (the Priya scenario), impact high. Mitigation: ADR-0007's fitness function fails the gate on any writer outside the adapter — the whole reason it is a decision with a check, not a comment.
