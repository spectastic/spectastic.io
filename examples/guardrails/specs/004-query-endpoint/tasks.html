4 · Phase 3a — US1 · Read a position over HTTP without ever writing one

Tests (write & fail first)

Test the endpoint against a live server — start HttpApi on port 0 over a SyncEventBus + InMemoryPositionRepository + PositionService with a recording subscriber; book t-1 AAPL +100 directly; then with java.net.http.HttpClient: GET /positions/AAPL → 200 and body {"instrument":"AAPL","quantity":100}; GET /positions/MSFT → 404 and {"error":"unknown instrument"}; PUT /positions/AAPL → 405; finally assert the recorder holds exactly the one booking event and find("AAPL") is still 100 — the observable for “no request mutates a position”. src/test/java/xyz/briancorbin/pk/hex/http/PositionsEndpointTest.java

Implementation

Implement the server wrapper — HttpApi(String host, int port) over HttpServer.create; handle(String path, HttpHandler), start(), stop(), port() (the bound port, for port 0). src/main/java/xyz/briancorbin/pk/hex/http/HttpApi.java
Implement the positions handler — context /positions/; non-GET → 405 with an Allow: GET header; path must be exactly one non-empty segment after the prefix, else 404; lookup → 200 Json.position or 404 Json.error("unknown instrument"); Content-Type: application/json on every body (spec FR-001, FR-002). src/main/java/xyz/briancorbin/pk/hex/http/PositionsHandler.java
Wire the process — Main: PK_PORT (default 8080), PK_DB (default data/pk); H2Database.open, SyncEventBus, JdbcPositionRepositoryAdapter, RiskExposureView, PnlRevaluer, PositionService, HttpApi with the positions handler; log the bound port; no java.sql import. src/main/java/xyz/briancorbin/pk/Main.java
Exercise the endpoint as a process — ./gradlew run in the background, then curl -si localhost:8080/positions/AAPL returns 404 {"error":"unknown instrument"} on a fresh store; ./gradlew test --tests '*PositionsEndpointTest' green; stop the process.

Closes FR-001, FR-002, NFR-001, SC-001.
